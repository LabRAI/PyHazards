Description
-----------

``unet3d`` is MONAI's ``UNet``: an encoder-decoder in which each level down-samples with one strided convolution and up-samples with one strided transposed convolution applied to the concatenation of the skip feature and the up-sampled deeper feature, each followed by instance norm, dropout and PReLU. MONAI documents it as the "enhanced" residual U-Net of Kerfoot et al. (2018); with ``num_res_units > 0`` every unit becomes a residual unit.

TS-SatFire calls it U-Net / U-Net-3D, but with ``num_res_units=0`` (its setting) it is neither Ronneberger et al.'s U-Net nor Cicek et al.'s 3D U-Net (2016): there is one convolution per level and side instead of two, no max pooling, no batch norm and no residual connection. The port follows MONAI 1.3.2 with its parameter names, so MONAI state dicts load with ``strict=True``.

With the defaults (``spatial_dims=3``) the model is TS-SatFire's U-Net-3D: input ``(batch, time, channels, H, W)``, 3D convolutions over (time, H, W) with stride (1, 2, 2) at every level so time is never down-sampled, widths 64-1024, and two-class logits averaged over time to ``(batch, 2, H, W)``. ``spatial_dims=2`` gives TS-SatFire's single-image U-Net (stride 2 at every level, input ``(batch, channels, H, W)``).

- **Checked configuration:** TS-SatFire's UNet(spatial_dims=3, in_channels=43, out_channels=2, channels=(64, 128, 256, 512, 1024), strides=(1, 2, 2)) from spatial_models/unet.py at da75732 (MONAI 1.3.2 code whose only change is one stride shared by all levels; the repository has no license and is used only as a test oracle), with its outputs averaged over time; MONAI 1.3.2 UNet(spatial_dims=2, in_channels=8, out_channels=2, same channels, strides=(2, 2, 2, 2)) for the 2D baseline (10,552,458 parameters); and 1D/2D/3D MONAI configurations with residual units, batch norm, ReLU, dropout, larger kernels and non-uniform per-level strides. Forward passes use 32x32 (3D, T=2) and 64x64 (2D) inputs instead of 256x256 to keep the CPU test fast.
- **Parameter count:** 31,712,970
- **Verified:** parameter count, seeded initialisation, parameter names and shapes, forward outputs
- **Oracle test:** ``tests/oracle/test_unet3d_oracle.py``
- **Deviation:** TS-SatFire averages the 3D logits over time in its training script (``outputs.mean(2)``); here that read-out is part of the model (``time_reduction="mean"``), which also takes PyHazards' ``(batch, time, channels, H, W)`` layout instead of ``(batch, channels, time, H, W)``.
- **Deviation:** Activations and norms are given by name and limited to ``"prelu"`` / ``"relu"`` and ``"instance"`` / ``"batch"`` (or ``None``); MONAI also accepts other layer names and ``(name, kwargs)`` tuples. ``dropout`` is a rate (MONAI's default ``dropout_dim=1``).
- **Deviation:** Configurations the reference rejects late or not at all -- too few strides, even kernel sizes, spatial sizes not divisible by the stride product (a size-mismatch RuntimeError in the reference) -- raise ValueError up front.
- **Deviation:** The paper reports 31.7M parameters for U-Net-3D across all three tasks; the prediction configuration with 43 input channels has 31,712,970 (31,652,490 with the 8-channel active-fire / burned-area input).

Notes
-----

- Every spatial size must be divisible by the product of the strides along that dimension: 16 for height and width with the default four levels; time is never down-sampled.
- The default two output channels follow TS-SatFire (sigmoid Dice loss on both in its released script); use out_channels=1 for a single-logit binary head.
- time_reduction='none' returns per-date maps (batch, classes, time, H, W), as TS-SatFire uses for its active-fire and burned-area tasks.
- strides follow MONAI (one entry per level, each an int or one value per dimension); stride_mode='shared' takes TS-SatFire's single strides=(1, 2, 2) literally and builds the same network as strides=[(1, 2, 2)] * 4.
- The top decoder unit is a bare transposed convolution (no norm or activation), so the output is unnormalised logits, as in MONAI.
