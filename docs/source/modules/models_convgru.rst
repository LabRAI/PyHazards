ConvGRU
=======

Overview
--------

``convgru`` runs a stack of convolutional GRU cells over a ``(batch, time, channels, height, width)`` sequence and maps the hidden state of the last time step to per-pixel logits with a ``Conv2d`` head. Each cell follows Ballas et al.: one convolution over ``[x_t, h_{t-1}]`` gives the update and reset gates, a second convolution over ``[x_t, r * h_{t-1}]`` gives the candidate, and ``h_t = (1 - z) * h_{t-1} + z * tanh(candidate)``.

Description
-----------

``convgru`` runs a stack of convolutional GRU cells over a ``(batch, time, channels, height, width)`` sequence and maps the hidden state of the last time step to per-pixel logits with a ``Conv2d`` head. Each cell follows Ballas et al.: one convolution over ``[x_t, h_{t-1}]`` gives the update and reset gates, a second convolution over ``[x_t, r * h_{t-1}]`` gives the candidate, and ``h_t = (1 - z) * h_{t-1} + z * tanh(candidate)``.

The default is the Conv-GRU baseline of FireCastNet (Michail et al., Scientific Reports 2025), as in its ``configs/conv-gru-config.yaml``: 11 SeasFire variables, one layer of 128 hidden channels, 5x5 kernels, a dense 64x64 logit map trained with BCE on every pixel. FireCastNet's code has no license, so the module is written from the equations; it is checked against FireCastNet's ``ConvGRUSeg``, whose state dicts load with ``strict=True``, and gives identical outputs and seeded initial weights.

Reproduction
------------

- **Reference implementation:** `https://github.com/SeasFire/firecastnet <https://github.com/SeasFire/firecastnet>`__ at ``dc0d131`` (none (no LICENSE file; seasfire/backbones/conv_gru.py is used only as the test oracle, not copied))
- **Checked configuration:** configs/conv-gru-config.yaml: ConvGRULit(input_dim_grid_nodes 11, hidden_layers 1, hidden_dim 128, kernel_size [5, 5]) -> ConvGRUSeg(..., num_classes=1), 64x64 patches, checked on (batch, 12, 11, 64, 64) inputs, also with all-zero (padding) steps; the paper's 64 hidden channels (361,793 parameters); a three-layer model with two classes (outputs and input gradients).
- **Parameter count:** 1,337,985
- **Verified:** parameter count, seeded initialisation, parameter names and shapes, forward outputs
- **Oracle test:** ``tests/oracle/test_convgru_oracle.py``
- **Deviation:** The reference looks for all-zero (padding) time steps and, if there are any, re-indexes the per-step outputs passed to the next layer with a batch-sized index (giving a ``(batch, batch, ...)`` tensor). This never changes the output of the one-layer model and breaks deeper ones. The port does not look for padding: padded steps update the state, as they do in the one-layer reference.
- **Deviation:** The head's padding is ``(kernel - 1) // 2`` per dimension; the reference uses the first kernel dimension for both, which only differs for non-square kernels.
- **Deviation:** Only ``task="segmentation"`` exists: the reference maps a sequence to one map of logits and has no frames-to-frames form. The ConvGRU baseline of Shi et al. (2017), a frame forecaster with a different cell (reset gate after the state convolution, leaky ReLU), is ``build_model("trajgru", task="forecasting", layer_type="ConvGRU")``.

Notes
-----

- Paper and code differ, and the code is followed. Hidden size: the paper (Sec. 5.1) gives the Conv-GRU "a single hidden layer with 64 hidden units" (also ConvGRULit's default), the configuration file 128 (the default here; ``hidden_dim=64`` gives the paper's size). Equations: the paper writes the candidate as ``tanh(W_xh * x + r . (W_hh * h) + b)``, reset gate after the state convolution, while the code, like Ballas et al. (Eq. 7), applies it before: ``tanh(W * [x, r . h])``. Read-out: the paper describes a (2r+1)x(2r+1) grid around each location and MLP layers that reduce it to one prediction; the code predicts a dense 64x64 map with a 5x5 convolution and BCE over all pixels. Training: the paper uses AdamW, lr 1e-3, SGDR (cycles of 10 and 40 epochs) and weight decay 1e-7; the configuration file lr 1e-3, weight decay 1e-8, gradient clipping 0.5, 50 epochs, 12 input steps and a target shift of 16.

- Input layout and preprocessing: ConvGRULit permutes SeasFire batches from ``(B, C, T, H, W)`` to ``(B, T, C, H, W)``, the layout used here. Variables are prepared by FireCastNet's data module (log1p for tp and pop_dens, standardisation; see the ``firecastnet`` card).
