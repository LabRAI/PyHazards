SwinLSTM
========

Overview
--------

``swinlstm`` replaces the convolutions of ConvLSTM with Swin Transformer blocks. Each frame is cut into 2x2 patches and embedded. In a SwinLSTM cell the patch tokens and the previous hidden state are layer-normalised, concatenated and projected back to the token width, passed through (shifted-)window attention blocks, and the result F updates a simplified LSTM: ``C_t = sigmoid(F) * (tanh(F) + C_{t-1})``, ``H_t = sigmoid(F) * tanh(C_t)``. A 3x3 transposed convolution with stride 2 and a sigmoid reconstruct the next frame. SwinLSTM-D (``variant="d"``, the default) has four cells joined by patch merging and patch expanding (embedding 128, window 4, heads 4 and 8); SwinLSTM-B (``variant="b"``) has cells at a single resolution.

Description
-----------

``swinlstm`` replaces the convolutions of ConvLSTM with Swin Transformer blocks. Each frame is cut into 2x2 patches and embedded. In a SwinLSTM cell the patch tokens and the previous hidden state are layer-normalised, concatenated and projected back to the token width, passed through (shifted-)window attention blocks, and the result F updates a simplified LSTM: ``C_t = sigmoid(F) * (tanh(F) + C_{t-1})``, ``H_t = sigmoid(F) * tanh(C_t)``. A 3x3 transposed convolution with stride 2 and a sigmoid reconstruct the next frame. SwinLSTM-D (``variant="d"``, the default) has four cells joined by patch merging and patch expanding (embedding 128, window 4, heads 4 and 8); SwinLSTM-B (``variant="b"``) has cells at a single resolution.

``forward`` runs the official rollout: a warm-up phase over the first ``T_in - 1`` frames, then autoregressive prediction starting from the last input frame, each predicted frame being the next input. ``include_warmup=True`` also returns the warm-up predictions, which the official L2 loss compares with the shifted input frames; ``step`` is the official single-step forward. The port matches the official code in eval and train mode (stochastic depth), and the released Moving-MNIST SwinLSTM-D weights load with ``strict=True``.

Sim2Real-Fire compares SwinLSTM with other forecasters for fire-area forecasting and backtracking but published no configuration for it. ``task="segmentation"`` is a PyHazards adaptation that predicts one next-step fire mask from a sequence of rasters.

Reproduction
------------

- **Reference implementation:** `https://github.com/SongTang-x/SwinLSTM <https://github.com/SongTang-x/SwinLSTM>`__ at ``4425bcf`` (MIT (code and the released weights in Pretrained/))
- **Checked configuration:** configs.py defaults, which are the Moving-MNIST setting of paper Table 1: SwinLSTM-D, 64x64x1 frames, patch 2, embedding 128, depths_down [2, 6], depths_up [6, 2], heads [4, 8], window 4, drop-path rate 0.1, 10 -> 10 frames. Checked with the released weights Pretrained/trained_model_state_dict (functions.model_forward_multi_layer rollout, single steps and the segmentation adaptation), with seeded initialisation and a train-mode rollout (stochastic depth); SwinLSTM-B with the configs.py defaults (depths [12], 2,778,417 parameters) and the Human3.6m setting (128x128x3, 2,781,747), a two-cell SwinLSTM-B and a two-level SwinLSTM-D with two input channels, each with seeded initialisation and eval and train rollouts (functions.model_forward_single_layer / model_forward_multi_layer).
- **Parameter count:** 20,191,969
- **Verified:** parameter count, seeded initialisation, parameter names and shapes, forward outputs, official pretrained weights
- **Oracle test:** ``tests/oracle/test_swinlstm_oracle.py``
- **Deviation:** ``patch_size`` must be 2. The reference reconstruction layer (3x3 transposed convolution, stride 2) restores the input size only for 2x2 patches, so the released code cannot run the paper's patch-4 settings (KTH, TaxiBJ) either; other patch sizes raise ``ValueError``.
- **Deviation:** The model's ``forward`` takes the whole sequence ``(batch, T_in, C, H, W)`` and runs the rollout of the official ``functions.py`` (warm-up, then autoregressive prediction); the reference model's ``forward`` is one time step, available here as ``step`` with the same arguments and return values.
- **Deviation:** The reference SwinLSTM-D constructor passes no dropout or drop-path arguments (dropout 0, attention dropout 0 and drop-path rate 0.1 are fixed); here they are arguments with those defaults. Zero initial states take the input's dtype (the reference creates float32 zeros).
- **Deviation:** ``task="segmentation"`` (SwinLSTMSegmenter) is a PyHazards adaptation, not from Sim2Real-Fire: the reconstruction layer has one output channel (``out_chans``; every other parameter has the shape of the forecasting model), the input frames go through the reference rollout with one prediction step, and that frame is returned before the final sigmoid, as logits ``(batch, 1, H, W)``. Its state dict keys are those of the forecasting model (no prefix).

Programmatic Use

.. code-block:: python

   import torch
   import torch.nn.functional as F
   from pyhazards.models import build_model

   # Official Moving-MNIST SwinLSTM-D: 10 frames of 64x64x1 in [0, 1] -> the next 10 frames.
   model = build_model(name="swinlstm", task="forecasting")  # 20,191,969 parameters
   # Released weights: model.load_state_dict(torch.load("Pretrained/trained_model_state_dict"))
   inputs, targets = torch.rand(2, 10, 1, 64, 64), torch.rand(2, 10, 1, 64, 64)
   future = model(inputs)  # (2, 10, 1, 64, 64)

   # Official training objective: L2 over the 9 warm-up and 10 predicted frames.
   outputs = model(inputs, include_warmup=True)  # (2, 19, 1, 64, 64)
   loss = F.mse_loss(outputs, torch.cat([inputs[:, 1:], targets], dim=1))

   # PyHazards adaptation: next-day fire-mask logits from 3 daily rasters with 6 channels.
   seg = build_model(name="swinlstm", task="segmentation", in_channels=6, img_size=64)
   logits = seg(torch.randn(2, 3, 6, 64, 64))  # (2, 1, 64, 64)

Notes
-----

- With the official ``depths_up`` [6, 2] the decoder runs 2 Swin blocks at the deepest level and 6 at the next, because the reference indexes ``depths_up`` (and the head counts) from the deepest level: the network has 2 + 6 blocks on the way down and 2 + 6 on the way up, where paper Table 1 lists (2, 6, 6, 2). Decoder cells also take their level's stochastic-depth rates in reverse block order. Both are kept, since the released weights follow them.

- ``Upsample.patch_embed`` is created by the reference but never used in its forward pass; it is kept (896 parameters) so that the official checkpoint loads with ``strict=True``.

- Frames are expected in [0, 1] (pixels / 255 for Moving MNIST); predictions are sigmoid outputs. Any frame size whose token grid (size / 2) can be halved once per level and split into whole windows works; Sim2Real-Fire's 256x256 frames give 128, 64 and 32 tokens per side.

- Sanity check of the released weights through this port: MSE 18.8 per frame (squared error summed over the 64x64 pixels, averaged over the 10 predicted frames) on 32 sequences generated by the official Moving_MNIST class from MNIST digits 10000-13000. The paper reports 17.7 on the standard Moving MNIST test set, which was not re-evaluated here.
