Description
-----------

``random_forest`` is a scikit-learn ``RandomForestClassifier(n_estimators=100, max_depth=10, min_samples_split=2, min_samples_leaf=1, random_state=123)`` (Breiman, 2001) with the configuration of the official random-forest notebook of Kondylatos et al. (GRL 2022). It takes the daily tensor ``(batch, 10, 25)`` of the ``wildfire_forecasting`` LSTM (10 dynamic, 5 static and 10 land-cover columns per day) or ready-made features ``(batch, 35)``, and returns ``(batch, 2)`` log-probabilities over (no fire, fire).

Daily tensors are turned into the paper's instance features exactly as the notebook does: the mean of the 10 dynamic variables over the ten days (ignoring missing values), the dynamic variables on the last day (t-1), the 5 static variables and the 10 Corine Land Cover fractions. ``kondylatos_instance_features`` exposes that construction.

The model is an ``nn.Module`` wrapper (``EstimatorModule``) around the fitted forest, not a neural network: fit it with ``model.fit(inputs, targets)``, after which ``forward`` returns the log of ``predict_proba``. It has no parameters, its outputs carry no gradient, and ``pyhazards.engine.Trainer.fit`` refuses it with an explanation; ``Trainer.evaluate`` and ``Trainer.predict`` work on the fitted model. ``task="regression"`` builds the matching ``RandomForestRegressor``.

- **Checked configuration:** notebooks/RF.ipynb: RandomForestClassifier(n_estimators=100, max_depth=10, min_samples_split=2, min_samples_leaf=1, random_state=123) fitted on the 35 instance features the notebook builds from FireDataset_npy(access_mode='temporal', clc='vec') with the 10 dynamic and 5 static variables of the paper. The oracle test runs the notebook's own cells on synthetic data and requires identical features, predicted probabilities and labels; the PyHazards input is the LSTM's daily tensor built by the reference combine_dynamic_static_inputs.
- **Verified:** forward outputs
- **Oracle test:** ``tests/oracle/test_classical_oracle.py``
- **Deviation:** The notebook reads (dynamic, static, land cover) separately from the dataset; PyHazards reads the concatenated daily tensor of ``wildfire_forecasting`` (or ready-made features) and takes the static and land-cover values from its last day. The values are the same because that tensor repeats them over the ten days.
- **Deviation:** The reference repository does not pin scikit-learn; the oracle compares the two under the installed release (1.7.2 when checked).

Programmatic Use
----------------

.. code-block:: python

   from pyhazards.datasets import load_dataset
   from pyhazards.models import build_model

   data = load_dataset("wildfire_danger_synthetic", samples=120).load()
   train, test = data.get_split("train"), data.get_split("test")

   model = build_model(name="random_forest", task="classification")
   model.fit(train.inputs, train.targets)  # (n, 10, 25) daily tensors -> 35 features
   log_probs = model(test.inputs)
   danger = log_probs.exp()[:, 1]  # = model.predict_proba(test.inputs)[:, 1]
   print(log_probs.shape)  # (18, 2)

   model.save("random_forest.joblib")  # EstimatorModule.load(path); joblib = pickle, trusted files only

Notes
-----

- Not trained by gradient descent: ``Trainer.fit`` raises ``TypeError``; call ``model.fit(inputs, targets)`` on the whole training split (the notebook fits on the training set only and uses neither the validation split nor early stopping). Calling the model before ``fit`` raises ``sklearn.exceptions.NotFittedError``.

- ``forward`` returns ``log(predict_proba)``; a forest often gives a class probability of exactly 0, which becomes ``-inf``. ``predict_proba`` and ``predict`` return the scikit-learn arrays; the notebook reports precision, recall and F1 of ``predict`` (threshold 0.5) and AUROC / AUPRC of the fire probability.

- ``state_dict()`` is empty, so torch checkpoints do not contain the trees. Persist the fitted model with ``model.save(path)`` and ``EstimatorModule.load(path)`` (joblib). Loading unpickles the file and can execute code: only load files you trust.

- Features are computed in float64 like the notebook. The notebook uses the dataset's float64 values while ``combine_dynamic_static_inputs`` casts the LSTM input to float32, so pass float64 daily tensors to reproduce the notebook's features bit for bit.

- At the pinned commit the dataset class validates on 2020 and tests on 2021, so the notebook's training split is 2009-2019; the paper trains on 2009-2018, validates on 2019 and tests on 2020 and 2021. Its negatives are drawn with an unseeded ``random.sample`` and its training loader shuffles, so the paper's forest cannot be rebuilt exactly; the same samples in the same order give the same forest.

- The benchmark smoke configs evaluate models without training, so this entry has none: fit the model first and pass it to ``BenchmarkRunner.run(model=...)``. With ``task="regression"`` the same hyperparameters are used, which no paper prescribes.
