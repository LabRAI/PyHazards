Prithvi-EO-2.0 BurnScars
========================

Overview
--------

``prithvi_burnscars`` is the released Prithvi-EO-2.0-300M-BurnScars model. Its encoder is the Prithvi-EO-2.0-300M masked-autoencoder ViT (ViT-L/16 with a 3D patch embedding and fixed 3D sin/cos positions, pretrained on 4.2M multi-temporal HLS samples). The outputs of encoder blocks 6, 12, 18 and 24 are reshaped to maps, turned into a four-level pyramid (learned transposed convolutions up, max pooling down) and decoded by a U-Net decoder (512, 256, 128, 64 channels) into two classes: not burned and burn scar.

Description
-----------

``prithvi_burnscars`` is the released Prithvi-EO-2.0-300M-BurnScars model. Its encoder is the Prithvi-EO-2.0-300M masked-autoencoder ViT (ViT-L/16 with a 3D patch embedding and fixed 3D sin/cos positions, pretrained on 4.2M multi-temporal HLS samples). The outputs of encoder blocks 6, 12, 18 and 24 are reshaped to maps, turned into a four-level pyramid (learned transposed convolutions up, max pooling down) and decoded by a U-Net decoder (512, 256, 128, 64 channels) into two classes: not burned and burn scar.

The modules are a plain-PyTorch port of the official ``prithvi_mae.py`` and of TerraTorch 0.99.8 with segmentation_models_pytorch 0.4.0, the stack the checkpoint was trained with, keeping TerraTorch's parameter names. ``pretrained=True`` downloads the 1.3 GB checkpoint from Hugging Face (pinned revision and sha256, cached in torch.hub's checkpoint directory) and loads it with ``strict=True``; no weights ship with PyHazards. Without it the model is randomly initialised exactly like TerraTorch's.

Reproduction
------------

- **Reference implementation:** `https://github.com/torchgeo/terratorch <https://github.com/torchgeo/terratorch>`__ at ``0.99.8`` (Apache-2.0)
- **Checked configuration:** EncoderDecoderFactory with the model_args of burn_scars_config.yaml (Hugging Face revision a3f2c41) under TerraTorch 0.99.8, segmentation_models_pytorch 0.4.0 and timm 1.0.15, at random initialisation and with the official Prithvi_EO_V2_300M_BurnScars.pt (sha256 0c5f9334...) loaded strictly after removing the Lightning "model." prefix. On the Hugging Face example chip T10SEH.2018190 the logits are identical (max absolute difference 0) and 79.5 % of the pixels are predicted burned.
- **Parameter count:** 324,204,674
- **Verified:** parameter count, seeded initialisation, parameter names and shapes, forward outputs, official pretrained weights
- **Oracle test:** ``tests/oracle/test_prithvi_oracle.py``
- **Deviation:** Padding: TerraTorch 0.99.8 reflect-pads the bottom/right edge to a multiple of the patch size (16) and then fails in the U-Net decoder whenever the token grid is odd; the port pads to a multiple of 32 (as later TerraTorch releases do, but at the bottom/right), which gives identical outputs for every size the reference accepts.
- **Deviation:** Non-square inputs: TerraTorch 0.99.8 swaps height and width when resizing the position table and reshapes tokens as a square grid, so non-square inputs fail or come out scrambled. The port uses the true (H, W) token grid, as the official prithvi_mae.py does. Square inputs, including the official 512 x 512 chips, are unaffected.
- **Deviation:** With num_classes=1 TerraTorch squeezes the class dimension; the port keeps (B, 1, H, W).

Programmatic Use

.. code-block:: python

   import torch
   from pyhazards.models import build_model
   from pyhazards.models.prithvi_burnscars import BURN_SCARS_MEAN, BURN_SCARS_STD

   # Official weights: about 1.3 GB, downloaded once from Hugging Face.
   model = build_model(name="prithvi_burnscars", task="segmentation", pretrained=True).eval()
   reflectance = torch.rand(1, 6, 512, 512)  # HLS Blue, Green, Red, NIR narrow, SWIR 1, SWIR 2 in 0-1
   mean = torch.tensor(BURN_SCARS_MEAN)[:, None, None]
   std = torch.tensor(BURN_SCARS_STD)[:, None, None]
   with torch.no_grad():
       logits = model((reflectance - mean) / std)
   burn_scar = logits.argmax(dim=1)  # 1 = burn scar
   print(logits.shape)  # (1, 2, 512, 512)

Notes
-----

- Post-fire mapping, not forecasting: the model maps burned area in one image taken after a fire. It is not linked to the wildfire benchmark's danger or spread tasks, which it does not solve.

- Input: HLS surface reflectance in 0-1 (digital numbers / 10000) of Blue, Green, Red, NIR narrow, SWIR 1 and SWIR 2, standardised per band with BURN_SCARS_MEAN and BURN_SCARS_STD; shape (B, 6, H, W) or (B, 6, 1, H, W). The official chips are 512 x 512. Pixels labelled -1 (no data, clouds) were ignored in training.

- Newer TerraTorch releases (checked: 1.2.13 with smp 0.5.0) resize the last U-Net block to the skip resolution instead of upsampling it by two. With the same weights that changes the logits by up to 1.6 and 0.37 % of the predicted pixels on the example chip. PyHazards keeps the training-time behaviour: the official demo pins TerraTorch 0.99.8, and the checkpoint was written by Lightning 2.5.0.post0, which 0.99.8 pins.

- The Prithvi-EO-2.0 paper (Table V) reports a different set-up: UperNet decoder, chips resized to 448 and cropped to 224, mean of ten seeds; test mIoU 88.6 and burn-scar IoU 79.9 for the 300M encoder. The test metrics were not re-evaluated in PyHazards.

- Weights are cached in torch.hub's checkpoint directory (cache_dir= overrides it); pass weights_path= to load an existing copy offline, and set HF_ENDPOINT to use a Hugging Face mirror.
