Description
-----------

``xgboost`` wraps ``xgboost.XGBClassifier`` (Chen & Guestrin, KDD 2016), the second tree baseline of Kondylatos et al. (GRL 2022). Like ``random_forest`` it takes the ``wildfire_forecasting`` daily tensor ``(batch, 10, 25)`` or ready-made features ``(batch, 35)``, builds the paper's instance features (ten-day mean and last-day value of the 10 dynamic variables, 5 static variables, 10 land-cover fractions), and returns ``(batch, 2)`` log-probabilities over (no fire, fire).

The paper gives the XGBoost hyperparameters only in its Supporting Information (Text S2), which has not been read, and the official repository has no XGBoost code. This entry therefore uses the library defaults of xgboost 3.2.0 (100 boosting rounds, maximum depth 6, learning rate 0.3, histogram trees with 256 bins, no subsampling, L2 regularisation 1, binary logistic objective). Any of them can be overridden through the builder.

``xgboost`` is an optional dependency (``pip install 'pyhazards[xgboost]'``, or the CPU-only ``xgboost-cpu``), imported only when the model is built. As for ``random_forest``, the module is fitted with ``model.fit(inputs, targets)`` and refused by ``Trainer.fit``.

Used In
-------

- `Wildfire Danger Prediction and Understanding With Deep Learning <https://doi.org/10.1029/2022GL099368>`_ (`repo <https://github.com/Orion-AI-Lab/wildfire_forecasting>`__): Kondylatos et al., Geophysical Research Letters 49(17), e2022GL099368. XGBoost on the instance-based data set (dynamic inputs at day t-1, their average over days t-1..t-10, static features) of the daily 1 km Greek / Eastern Mediterranean datacube; train 2009-2018, test 2020 and 2021. Hyperparameters in Supporting Information Text S2 (not read). Test results (Table 1, 2020 / 2021): precision 0.852 / 0.867, recall 0.723 / 0.720, F1 0.782 / 0.786 (TP 888 / 3,172, FP 154 / 488, TN 2,302 / 8,326, FN 340 / 1,235); random forest F1 0.703 / 0.778, LSTM 0.804 / 0.879.

Reproduction
------------

- **Reference implementation:** none released; rebuilt from the paper.
- **Paper configuration:** Kondylatos et al. (2022), Section 3: XGBoost on the instance-based features. PyHazards builds the features as the official random-forest notebook (notebooks/RF.ipynb) does and uses xgboost.XGBClassifier() with the defaults of xgboost 3.2.0; tests/oracle/test_classical_oracle.py checks that its predictions equal those of XGBClassifier() 3.2.0 fitted on the notebook's features.
- **Oracle test:** ``tests/oracle/test_classical_oracle.py``
- **Deviation:** Hyperparameters are pending the paper's Supporting Information (Text S2, behind the Wiley site and not read): the xgboost 3.2.0 library defaults are used, which need not match the paper's model or reproduce its scores.
- **Deviation:** The library defaults depend on the xgboost release (2.0 switched to histogram trees and an estimated base score); other releases may give different predictions.

Programmatic Use
----------------

.. code-block:: python

   from pyhazards.datasets import load_dataset
   from pyhazards.models import build_model

   data = load_dataset("wildfire_danger_synthetic", samples=120).load()
   train, test = data.get_split("train"), data.get_split("test")

   model = build_model(name="xgboost", task="classification")  # needs pyhazards[xgboost]
   model.fit(train.inputs, train.targets)
   print(model(test.inputs).shape)  # (18, 2) log-probabilities

Notes
-----

- Install with ``pip install 'pyhazards[xgboost]'`` (``xgboost>=2.0``) or ``pip install xgboost-cpu`` (same module, no CUDA/NCCL wheels). Without it, building the model raises an ``ImportError`` that says so, and the catalog smoke test is skipped.

- ``n_jobs`` defaults to all available cores (``OMP_NUM_THREADS`` caps it); pass ``n_jobs`` on shared machines.

- The fitting, ``forward``, persistence (``save`` / ``EstimatorModule.load``, joblib) and ``Trainer`` behaviour are those of ``random_forest``.
