Rainformer
==========

Overview
--------

``rainformer`` stacks the input frames as channels and maps them to as many future frames (Bai et al., IEEE GRSL 2022). Four encoder stages (patch merging by 4, 2, 2, 2) and four decoder stages (patch expanding, concatenation with the encoder skip) each contain a feature-extraction balance module: a global unit of a window and a shifted-window self-attention block (each followed by channel attention), a local unit of two convolution-BatchNorm-ReLU layers and CBAM channel/spatial attention, and a gate fusion unit that mixes them as ``Z * global + R * local`` with sigmoid gates computed from both.

Description
-----------

``rainformer`` stacks the input frames as channels and maps them to as many future frames (Bai et al., IEEE GRSL 2022). Four encoder stages (patch merging by 4, 2, 2, 2) and four decoder stages (patch expanding, concatenation with the encoder skip) each contain a feature-extraction balance module: a global unit of a window and a shifted-window self-attention block (each followed by channel attention), a local unit of two convolution-BatchNorm-ReLU layers and CBAM channel/spatial attention, and a gate fusion unit that mixes them as ``Z * global + R * local`` with sigmoid gates computed from both.

The default is the official KNMI model of ``train.py``: 9 -> 9 frames of 288 x 288, hidden 96, heads 3/6/12/24, head dim 32, window 9, relative position bias; 187,661,990 parameters (104,976 of them the fixed shifted-window masks). The official code has no license, so the model is written from the paper and from the MIT-licensed Swin implementation the official code builds on (berniwal/swin-transformer-pytorch). Parameter names and creation order follow the official ``Net``, so the released KNMI checkpoint loads with ``strict=True`` and the same seed gives the same weights.

``task="forecasting"`` takes ``(batch, T, C, H, W)`` (or the official ``(batch, T * C, H, W)``) and returns the next ``T`` frames. ``task="segmentation"`` is a PyHazards adaptation for next-step fire masks: a 1x1 convolution (``segmentation_head``) maps the channels of the first predicted frame to ``out_channels`` logits ``(batch, 1, H, W)``; the Rainformer parameters keep their official names at the top level of the state dict.

Reproduction
------------

- **Reference implementation:** `https://github.com/Zjut-MultimediaPlus/Rainformer <https://github.com/Zjut-MultimediaPlus/Rainformer>`__ at ``c4e04e9`` (none (no LICENSE file; used only as a test oracle, not copied); the KNMI checkpoint states no licence and is used only as test data; the ported Swin parts are MIT (berniwal/swin-transformer-pytorch c921ebf914c6ea9734bb260ada395e3746c85402))
- **Checked configuration:** Net(input_channel=9, hidden_dim=96, downscaling_factors=(4, 2, 2, 2), layers=(2, 2, 2, 2), heads=(3, 6, 12, 24), head_dim=32, window_size=9, relative_pos_embedding=True) from train.py at 288 x 288 (einops 0.8.2): 187,661,990 parameters; seeded initialisation, eval/train outputs, gradients and BatchNorm statistics compared locally with PYHAZARDS_ORACLE_LARGE=1, and the released KNMI checkpoint (model1_1_100.pt from the repository's Google Drive link, sha256-pinned, 751 MB) loaded with strict=True into both models with identical outputs (all bit-identical). CI compares three narrow 288 x 288 models (hidden 8-16, windows 9 and 3, with and without relative position bias, two FEBM groups in stage 1 or 3).
- **Parameter count:** 187,661,990
- **Verified:** parameter count, seeded initialisation, parameter names and shapes, forward outputs, official pretrained weights
- **Oracle test:** ``tests/oracle/test_rainformer_oracle.py``
- **Deviation:** task="segmentation" (first predicted frame, 1x1 convolution to out_channels logits) is a PyHazards adaptation, not from Sim2Real-Fire, whose baseline heads are unpublished.
- **Deviation:** The official Net hard-codes the stage feature maps for 288 x 288 inputs (72/36/18/9 and back), which fixes the shapes of the gate LayerNorms; it runs only at that size with downscaling factors (4, 2, 2, 2). PyHazards derives the stage sizes from img_size and raises ValueError unless every stage map is divisible by window_size. Sim2Real-Fire's 256 x 256 frames give 64/32/16/8 maps, which window 9 does not divide, so Sim2Real-Fire must have changed the window size or the input size; which one is not published (unverified). Its own S2R-FireTr encoder uses the same Swin stage settings (hidden 96, heads 3/6/12, head dim 32) with window 8 at 256 x 256, and window_size=8 works here (181,876,886 parameters).
- **Deviation:** Input in the PyHazards layout (batch, time, channels, H, W) is flattened time-major to the official (batch, time * channels, H, W) and reshaped back; the official layout is also accepted. The relative-position index is a non-persistent buffer (it moves with the model's device) instead of a plain tensor attribute; the state dict is unchanged.

Programmatic Use

   import torch
   from pyhazards.models import build_model

   # Official KNMI configuration: 9 radar frames of 288 x 288 -> the next 9 frames.
   model = build_model(name="rainformer", task="forecasting")
   # model.load_state_dict(torch.load("model1_1_100.pt", map_location="cpu"))  # official KNMI weights

   # PyHazards next-step fire-mask adaptation on 256 x 256 frames (window 8 divides 64/32/16/8).
   seg = build_model(name="rainformer", task="segmentation", in_channels=4, history=3, img_size=256, window_size=8)
   print(seg(torch.randn(1, 3, 4, 256, 256)).shape)  # (1, 1, 256, 256)

Notes
-----

- The gate LayerNorms normalise over (channels, height, width) with elementwise affine weights (27,371,520 of the default parameters), so a model only runs at the img_size it was built for and its parameter count depends on that size.
- Kept from the official code because they change outputs or parameter counts: the gate fusion unit computes Z * g + R * l (the paper's Eq. 8 also convolves g and l; those convolutions, conv_2 and conv_3, are built but unused); every window attention is followed by a channel attention with separate average- and max-pool MLPs; the relative position bias is one table shared by all heads; decoder blocks use an MLP of only twice their width; the shifted-window masks are parameters without gradient.
- With layers > 2 per stage, the official stage applies every FEBM group to the same stage input and keeps only the last group's output; PyHazards reproduces this. The official layers = (2, 2, 2, 2) has one group per stage.
- The official KNMI checkpoint (Google Drive file 1LyLOJI9sf1sdZE1FwyTLPEGEcUuvXQc3, model1_1_100.pt, sha256 e3d5e4e59b32f13a74c7ffdc02ae65f9da3362c036b60e73e46dffe8721ae6b2) states no licence and is not redistributed by PyHazards. train.py feeds KNMI rain maps multiplied by 4783 / 100 * 12.
- The official train.py uses Adam with learning rate 1e-3 and ReduceLROnPlateau, batch 24, and a balanced-MAE loss; the paper states 1e-4 and batch 16.
- Earthformer (Gao et al., NeurIPS 2022) benchmarks re-sized Rainformer variants on SEVIR (184.0M parameters) and Moving MNIST (19.2M); those configurations are not in the official repository.
