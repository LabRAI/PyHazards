Description
-----------

``floodcast`` is a compact PyHazards spatiotemporal network that maps ``(batch, history, channels, H, W)`` rasters to a next-step depth raster ``(batch, 1, H, W)``. It is not FloodCast. FloodCast's hydrodynamic module is the sequence-to-sequence GeoPINS: a physics-informed Fourier neural operator solving the 2-D shallow-water equations without training labels, trained per 16-step sequence and marched in time, with hard-encoded inflow boundaries.

Why it is not rebuilt from the paper (arXiv 2403.12226v1, the only open version; read in full): the paper gives the GeoPINS layout (MLP lift, FNO layers, MLP projection; GELU and a layer normalisation after each FNO layer in its PDE experiments), four space-time FNO layers with spatial modes 32 and temporal modes 4 for the flood model, the GeoPC loss (continuity and momentum residuals with Manning friction, initial-condition weight 10, finite differences) and the training schedule, but not the channel widths of the flood model (only the toy PDE experiments list widths 16 / 24 / 24 / 32 / 32), not the lifting / projection widths, and only "3 input channels: coordinate x, time t and initial condition" for a 2-D problem with three state variables. The released repository holds toy PDE examples and empty placeholders for the flood model and has no licence. A rebuild would therefore guess its size; it would be neither the paper's model nor checkable.

FloodCastBench's supervised FNO baseline (Xu et al., Scientific Data 12:431, 2025: 4 Fourier layers, the 12 lowest modes, width 20, one-shot over 19 steps from the initial depth plus coordinates and time; FNO+ adds terrain and rainfall) is not added either: FloodCastBench released only its data-generation code (no model code, no licence), so there is nothing to verify a port against, and the paper leaves the temporal modes open. The smoke configuration scores this stand-in on ``flood_inundation_synthetic`` (random rasters).
