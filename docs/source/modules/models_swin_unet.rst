Description
-----------

``swin_unet`` encodes the input with four Swin Transformer stages joined by patch merging, decodes it with mirrored Swin stages joined by patch-expanding layers and skip connections, and upsamples the last decoder tokens 4x into per-pixel logits (Cao et al., ECCV Workshops 2022). The default is Swin-Unet-Tiny: patch 4, embedding 96, depths (2, 2, 2, 2), heads (3, 6, 12, 24), window 7, input 224x224, drop-path rate 0.2.

The implementation is written from the paper and from the MIT-licensed Swin Transformer code, because the official Swin-Unet repository has no license. Parameter names and creation order match the official ``SwinTransformerSys``, so its state dicts load with ``strict=True`` and seeded initialisation is identical. ``pretrained="imagenet"`` reproduces the official initialisation: the Swin-T ImageNet-1k checkpoint fills the encoder and, mirrored, the decoder. Multi-day input ``(batch, time, channels, height, width)`` is flattened to ``time * channels`` channels, as WSTS+ does for its 5-day models.

Notes
-----

- Inputs must be img_size x img_size (224 by default); WSTS+ zero-pads its 128x128 tiles. The padding layout is not stated in the paper.
- The decoder mirrors the encoder depths. The official DECODER_DEPTHS option and the depths_decoder argument have no effect in the official code, so they are not exposed.
- Decoder blocks reuse the stochastic-depth rates of the matching encoder stage, as in the official code.
- With pretrained weights, tensors whose shape differs from Swin-T (the patch embedding when in_channels != 3) keep their random initialisation, as in the official load_from.
- WSTS+ loaded the Hugging Face release of Swin-T (microsoft/swin-tiny-patch4-window7-224, a conversion of the ImageNet-1k model); PyHazards loads the original microsoft/Swin-Transformer checkpoint with the official Swin-Unet key mapping.
