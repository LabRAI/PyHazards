WRF-SFIRE Outputs
=================

Fire-grid outputs of the coupled WRF-SFIRE atmosphere-fire model, read from wrfout files into spread rasters.

Overview
--------

WRF-SFIRE couples the WRF atmosphere model with SFIRE, a level-set fire-spread model with Rothermel rate of spread and two-way heat and moisture flux coupling (Mandel, Beezley and Kochanski, GMD 2011).

PyHazards does not run WRF-SFIRE, which is an MPI Fortran model built per machine, and reimplements none of it. It reads the fire-grid fields that a WRF-SFIRE run writes to its wrfout history files and turns them into wildfire.spread rasters and samples.

Data Characteristics
--------------------

- Fire-grid variables have dimensions (Time, south_north_subgrid, west_east_subgrid); the fire mesh is sr_x by sr_y times finer than the atmospheric grid, and the last sr_y rows and sr_x columns are padding, which the reader removes.
- TIGN_G is the fire arrival time in seconds since the simulation start where a cell has burned; unburned cells hold a time one fire step in the future.
- LFN is the level-set function; the fire region is LFN < 0, which the reader uses as the burned mask.
- FIRE_AREA (fraction of the cell on fire), FUEL_FRAC, FGRNHFX (ground heat flux, W/m^2), ROS and F_ROS (rate of spread, m/s), FLINEINT, NFUEL_CAT, ZSF, UF/VF and FXLONG/FXLAT can be read as extra fields. Names, units and descriptions follow Registry/registry.fire of release W4.4-S0.1.
- XTIME gives the output times in minutes since the simulation start; arrays are returned north-up by default (origin='upper') or in WRF's south-up order.

Typical Use Cases
~~~~~~~~~~~~~~~~~

- Training or evaluating spread models on physics-based simulations of chosen scenarios.
- Comparing learned spread models with a coupled atmosphere-fire model on the same domain.
- Extracting arrival-time maps and burned-area time series from WRF-SFIRE runs.

PyHazards Usage
---------------

Use load_dataset('wrf_sfire_spread', paths=...) for wildfire.spread samples, or read_wrf_sfire_fire_grid for the raw fire grid.

PyHazards only reads WRF-SFIRE outputs; producing them needs the official WRF-SFIRE build and its inputs (meteorology, fuels, topography), for example through wrfxpy.

Registry Workflow
~~~~~~~~~~~~~~~~~

Primary dataset name: ``wrf_sfire_spread``

.. code-block:: python

   from pyhazards.datasets import load_dataset
   from pyhazards.datasets.wrf_sfire import read_wrf_sfire_fire_grid

   # Next-frame spread samples: burned mask (LFN < 0) plus chosen fields -> next burned mask.
   data = load_dataset("wrf_sfire_spread", paths="run/wrfout_d01_*", horizon=1, features=("NFUEL_CAT", "ZSF")).load()
   train = data.get_split("train")
   print(train.inputs.shape, train.targets.shape)  # (N, 3, rows, cols), (N, 1, rows, cols)

   # Or the raw fire grid: arrival time (s since simulation start) and burned masks.
   grid = read_wrf_sfire_fire_grid("run/wrfout_d01_*", variables=("TIGN_G", "LFN", "FIRE_AREA"))
   print(grid.arrival_time().shape, grid.burned_masks().shape, grid.fire_dx)

- There is no synthetic fallback; paths must point at wrfout files from a real WRF-SFIRE run.
- Splits are chronological over the output frames of the run.
